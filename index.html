My opinion

A good idea, but the card alone is not the product

Pretty animated invitations already exist (Paperless Post, Greenvelope, Evite, Canva, and many Instagram sellers who make a video invite for a small fee). Competing on beautiful cards only is a race to the bottom. What hosts actually struggle with is the guest list: who is coming, how many seats each family gets, where everyone sits, and getting the photos back afterward. Your seating hall idea is the real differentiator. Build the product around the whole event, and use the cards as the entry point.

Demand 8/10

Every wedding needs invites. Digital is already normal via WhatsApp.

Differentiation 7/10

Seating + per-guest seat limits + photo wall is rare, especially with Arabic/RTL.

Willingness to pay 7/10

Weddings are emotional, high-budget events. $30–80 is small next to the hall bill.

Repeat usage 4/10

A couple marries once. Fix this with venues, planners and many event types.

Build difficulty 6/10

Card editor and seating drag-and-drop are the hardest parts.

Three strategic moves I would make

  • Sell to venues and planners, not only couples. A hall that uploads its own layout once brings you every couple who books it. That solves the "people marry once" problem.
  • Personalized guest links. Each family gets its own link with its name and an allowed seat count ("2 seats reserved for you"). This stops uninvited extras, which hosts really care about.
  • WhatsApp first. Most invites will be opened from a WhatsApp chat on a mid-range phone. The link preview image and a fast first load matter more than any 3D effect.

Where your ideas are strongest

  • SVG generated halls: correct call. Halls share one structure (stage, dance floor, tables), so a parametric generator covers 90% of venues today and becomes a hall designer later.
  • Default card values the customer can change: right model. Store each card as a config (colors, fonts, effects) so templates are data, not code.
  • Paid photo cloud: strong upsell, because it arrives after the event when the host is happy and storage has a real cost you can justify.
  • Three.js for every card: I would limit this. Use it for a few premium "3D" cards and build the rest with CSS/GSAP animation that loads fast everywhere.

The hall is stored as data

The SVG is drawn from a small JSON object. Venues save one of these, and the seating assignments reference table and chair ids. A future hall designer only edits this object.


    

    

      
Why SVG and not canvas or 3D

      
    
        
  • Every chair is a real element: clickable, accessible, and easy to drag guests onto.
    • 
        
  • Crisp on any screen and printable as a seating chart PDF for the hall staff.
    • 
        
  • Small: a 400-seat hall is a few KB, generated on the device.
    • 
        
  • Later you can add shapes (long banquet tables, sofas, a VIP row) by adding new table types to the same schema.

    Wallet pass
    
The invitation lives in the guest's phone wallet

    
After a guest confirms, they tap "Add to Wallet". The pass carries the couple's colors and names, the table number and the entry QR. On the day, it can appear on the lock screen when the guest is near the hall. The drawings follow the real field layouts of Apple Wallet event tickets and Google Wallet event passes; the QR codes are decorative.

  

  

    
    
    
  

  

    

      
How to build it

      
    
        
  • Apple Wallet: generate a signed .pkpass file on your server (event ticket style). Needs an Apple Developer account ($99/year) and a Pass Type ID certificate.
    • 
        
  • Google Wallet: create an event ticket class per event and an object per guest through the Google Wallet API, then show a "Save to Google Wallet" link. The issuer account is free.
    • 
        
  • The pass design comes from the card config: background color, text color, label color, names, and a strip or hero image rendered from the card.
    • 
        
  • Add the hall's location and the event date so the pass shows up near the hall on the day.
    • 
        
  • Passes can be updated after saving. If the time changes or the guest moves table, every saved pass updates.
    • 
      

    

    

      
Limits to plan for

      
    
        
  • Wallets use fixed templates: you choose colors, images and fields, not free layout. Animations stay in the web invite.
    • 
        
  • Some Android phones have no Google Wallet. Show the same pass as a page with "Save to home screen".
    • 
        
  • The pass QR is the same one used for check-in at the door, so wallet passes and the QR check-in add-on sell well together.
    • 
        
  • Pricing: included in Signature, $5 add-on on Premium.
    •

Pricing tactics that usually work for events

    
    
      
  • Let them build for free, charge when they send. People pay once they have invested time editing and want to share.
    • 
      
  • Bundles beat lists. Show Signature as "everything for the wedding" so add-ons feel like a deal inside it.
    • 
      
  • The Free badge is marketing. Every free invite reaches 50 people who may host their own event next.
    • 
      
  • Seasonal pricing. Wedding season and Eid holidays are peaks; run early-bird discounts before them.

    Tech
    
A stack that keeps invites fast on any phone

  

  

    
Cards as config
Each template is a JSON file: theme tokens (colors, fonts), sections (cover, names, details, gallery, RSVP) and an effects list where each effect has an on/off flag. One renderer draws all cards. New cards become design work, not code.

    
Animation
CSS and GSAP for most effects, Lottie for illustrated motion. Three.js only on Signature cards, loaded lazily after the first screen, with a still image fallback and respect for "reduce motion".

    
App
Next.js (or Nuxt/SvelteKit) with server rendering so the WhatsApp preview image and title work. Postgres for events, guests and seats. Full RTL support from day one.

    
Media
Object storage (S3 or Cloudflare R2) with automatic image resizing. Video through a streaming service so guests do not download a 200 MB file. Storage cost sets your photo cloud price.

    
Payments
Stripe where it is available, plus a local gateway for your region (for example Tap, PayTabs or HyperPay in the Gulf). Support Apple Pay and local cards.

    
Messaging
Start with "copy link" and WhatsApp share buttons. Add the WhatsApp Business API for automated reminders later, since each message costs money and needs approved templates.

  






  

    Roadmap
    
Ship the invite first, then the seating, then the platform

  

  

    
Weeks 1–2
Validate before coding
Make 3 cards by hand and sell them to 10 real couples through Instagram or friends. Talk to 5 wedding halls about the seating idea. If halls say yes, you have your channel.

    
Weeks 3–12
MVP
8–10 templates, the card editor, RSVP, personal guest links, payments, Arabic and English. Launch with Free and Premium.

    
Months 4–5
V2: the event tools
Seating planner on the SVG hall, QR check-in, reminders, photo wall. Launch Signature.

    
Months 6–9
V3: the platform
Venue Pro with the hall designer, template marketplace, vendor listings, thank-you cards.
